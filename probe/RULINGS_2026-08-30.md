## Ruling 1: step-change definitions are per-episode, pinned first

The HOME/AWAY definitions and the seven-day threshold of the
2026-08-16 rule bind the haiku spend_anomaly_v2 episodes and nothing
else. They do not generalize to other threads by default, and no
thread acquires a step-change count retroactively.

The fact that forced the ruling, stated so it cannot be discovered
later as a surprise: applied descriptively, the same definitions
would today read a ten-day consecutive observed away run on
gpt-5.6-terra / eq_alert_fraud_scoring (baseline modal C, 26
observed days) and a six-day run on eq_access_offboarding. Ten
exceeds the haiku threshold. No candidacy fires, because no rule
was pinned for those threads before their data existed, and pinning
one now, after reading the runs, would be exactly the post-hoc move
the 2026-08-16 rule was built to prevent. The discipline is the
point: a threshold crossed under a rule adopted after the crossing
is not a finding.

Going forward: any thread the operator wants under step-change
evaluation gets its own dated rule, pinned before its deciding
data, with its own definitions anchored to that item's baseline
modal. The count starts at the pin, never before it. The gpt
fraud_scoring run is recorded here as a descriptive observation
only; if the operator pins a rule for that thread, its clock starts
that day at zero.

## Ruling 2: the return watch answers one question, and marks extremes

Scope, pinned: probe/scripts/return_watch.py answers "has the
re-baselined item returned to its superseded reference," by the
criterion pre-registered in REBASELINE_DECISION_2026-08-23.md, and
nothing else. It is not general anomaly coverage for the slot
(CORRECTIONS_2026-08-30.md, E3): departures deeper than the away
state are the monitor's business once they leave the new band, and
sub-band shape changes are visible in the watch's daily TVD column
and in the derived counts, not flagged.

One widening, adopted with this ruling: the watch now marks any
post-rebaseline day whose distance from the superseded reference
exceeds every prior post-rebaseline day (FARTHEST-YET). No
threshold is involved, only running extremes, so nothing is tuned
and nothing can be tuned later; the Aug 26 excursion class
(3/7/0/0 at 0.85, the item's first zero-D day, unflagged by both
watchers when it happened) becomes visible in the watch output
without changing what the watch decides. The RETURN criterion is
untouched.

## Ruling 3: item class is defined by the item id prefix

For every analysis, the equipoise/decisive split is defined by the
item id: eq_ prefixed items are the designed-equipoise class (23 of
the bank's 68; 115 of 340 slots), all others decisive. This matches
the bank's authorship (items/items.py and
docs/equipoise_authoring_notes.md). The "class" field in the
baseline files means alarm-versus-sentinel only (every current slot
is "alarm"; there are no sentinels) and says nothing about
equipoise; DESIGN_LIMITATIONS.md fix 3, class annotations in the
verdict path, remains unimplemented and stays that way until after
the freeze. Any freeze-analysis number keyed on class uses the
prefix definition above, and the sign-inversion caveat
(DESIGN_LIMITATIONS.md, Limitation 4: for slots unanimous at
baseline, the frozen reference may itself be the anomalous state)
attaches to class-level claims wherever they are made.

## What these rulings do not do

No rule fires for any gpt thread. No verdict, band, baseline, K,
seed, or alarm-set member changes. The monitor stays byte-constant
through the 2026-09-26 freeze; the only code change adopted here is
the watch's extreme marker, which is analysis-side and decides
nothing.
